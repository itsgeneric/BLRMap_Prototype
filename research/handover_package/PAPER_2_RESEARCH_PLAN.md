# Paper 2 — Research Plan and Current Direction

## Working title
*Design and Empirical Evaluation of a Two-Wheeler-Aware Routing Framework for Urban Road Networks*

## Research focus
Paper 2 evaluates the broader framework and its ability to generate alternative routes, rather than repeating Paper 1's controlled algorithmic analysis. The user now wants a practical comparison against Google Maps and Waze, using the same manual route-collection method for all platforms to keep the study manageable.

## Proposed research questions
1. How does the proposed framework generate alternative routes across urban OD corridors?
2. How do its alternative-route count, diversity, overlap, detour, and runtime compare with a standard K-shortest-path baseline?
3. How do routes generated by the framework compare with manually collected Google Maps and Waze recommendations under matched OD conditions?
4. What can real-world Strava GPS observations tell us about route adherence and actual journey characteristics?

## Proposed commercial platform comparison
The user explicitly prefers a simple, consistent manual collection protocol for all three:
1. The user's own project.
2. Google Maps.
3. Waze.

Do not use Google Routes API for Google Maps while manually collecting Waze; the user wants the same manual procedure for both commercial apps.

Proposed procedure:
- Use the same origin and destination coordinates for each platform.
- Capture the recommended route and any alternatives shown.
- Record route distance and displayed ETA.
- Capture screenshots of route map and details.
- Record collection date/time and traffic/time window.
- Repeat at matched time windows if feasible.
- Use route geometries for turn counts and road-class exposure where route geometry can be extracted or reliably traced.
- Keep route ETA (app prediction) separate from actual Strava elapsed time.
- Avoid claiming one platform is better solely because it gives a shorter route.
- Document platform-specific limitations and traffic conditions.
